# Shared ERP deployment

This branch replaces browser-only persistence with an authenticated Node server and PostgreSQL. The intended no-paid-resources configuration is a Render Free web service plus a Supabase Free database. Do not deploy this branch as a static site.

## Setup

- Create the database in a **Free** Supabase organization. Do not provision paid Render Postgres.
- Use the Supabase IPv4-compatible session pooler connection URL in `DATABASE_URL`. Keep credentials only in Render environment variables.
- Set `DATABASE_SSL=true` for the external Supabase connection. TLS certificates must validate; do not disable certificate verification.
- Set `NODE_ENV=production`.
- For first boot, generate an administrator password and supply its scrypt hash as `ERP_ADMIN_HASH`. The format is generated by `hashPassword` in `store.js`. Never commit the password or hash to source control. After first boot, the password hash is held in the database and can be changed in the app.
- Build: `npm ci --omit=dev`. Start: `npm start`. Optional health check: `/healthz`.
- Render plan: `free`. No disk required; all shared business data, sessions and password hashes reside in PostgreSQL.
- PostgreSQL tables are in the non-public `erp_private` schema, not the Supabase public Data API schema.

## Migration

1. On the device and old URL with the existing data, choose Download backup.
2. Open the new server URL and sign in with the workspace password.
3. Choose Import backup. New records are merged; existing conflicting records are rejected. No automatic destructive replacement occurs.
4. Verify item, customer and invoice counts and a sample invoice. Sign in on a second device to check shared access.
5. Keep the old site and backup until migration is verified. Do not clear the original browser's data.

If this app is later served from an origin with legacy local data, the Import device records banner can import it directly. Data from another origin cannot be read automatically.

## Sync and limits

The app loads authoritative shared records on login and refreshes while idle every 15 seconds. An open edit form pauses refreshing. Writes use a database revision check; stale writes fail without overwriting other devices. Saving needs an internet connection. The service worker only caches app assets, never API responses.

This lightweight implementation uses one versioned JSONB document (up to 8 MB per request) for the single-business workspace. All signed-in users share the workspace password and can manage all records. It is not a multi-tenant app or individual-user role system.

A Supabase Free project may pause after low activity; resume it in the Supabase Dashboard. Render Free web services sleep when idle and wake automatically on a visit. Neither free service has an always-on SLA. Keep downloaded backups.

## Verification

Run `npm ci` and `npm test`. Tests exercise two authenticated sessions sharing data, stale-write rejection, invalid-data rejection, login and CSRF protection, password changes, database-error handling, and the item-entry/import UI. Tests use a PostgreSQL emulator and a DOM emulator; verify the actual hosted database and devices after deployment.
